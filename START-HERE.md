## Обязательный шаг перед запуском

В этой ветке ещё НЕ обновлены package.json и package-lock.json для PostgreSQL.
Нельзя считать npm ci достаточным для запуска до установки новых зависимостей.

```bash
npm ci
npm install pg
npm install -D @types/pg
```

Сохраните оба обновлённых файла зависимостей в следующем коммите. Lock-файл не редактировать вручную.

Добавьте в локальный .env переменную DATABASE_URL с реальными реквизитами PostgreSQL.
Существующие PORT, API_TOKEN, AUTHOR_LOGIN, AUTHOR_FULL_NAME оставьте.
Логин и ФИО должны точно совпадать с Moodle; не выводите секреты в общий чат.

```dotenv
DATABASE_URL=postgresql://APP_USER:URL_ENCODED_PASSWORD@HOST:5432/DATABASE
```

Это только формат. Для облака используйте TLS-параметры и CA по инструкции выбранной площадки.
Не отключайте проверку сертификата ради обхода ошибки. Не помещайте реальную строку в .env.example.
Добавьте в .env.example только пример с заглушками. Не коммитьте .env.

```bash
npx tsx scripts/init-db.ts
npm run typecheck
npm run build
npm run dev
```

Инициализация требует CREATE TABLE и CREATE INDEX. Выполняйте её владельцем учебной БД, затем используйте отдельную ограниченную роль приложения.
Если app-пользователь не может создавать таблицы, выполните db/001_tasks.sql через psql от владельца БД.
Скрипт init-db.ts запускается напрямую через tsx и не требует изменения tsconfig.

## Что проверить в браузере

1. Открыть http://localhost:3000/, ввести локальный API_TOKEN.
2. Проверить ФИО и логин. Выбрать пространство manual.
3. Вручную создать «Итоговая работа 24.10.2026: <ваш логин Moodle>» без угловых скобок.
4. Создать дополнительное дело; изменить, завершить, снять отметку и удалить.
5. Перезапустить сервер и войти снова: персональное дело осталось.
6. Независимо изменить название строки в PostgreSQL, нажать «Обновить»: новое название отобразилось.
7. Проверить при ширине 360px и только с клавиатурой.

## Реализация

Серверная длина title считается в Unicode code points; PostgreSQL char_length использует тот же подход.
Все выборки ограничены owner_login из конфигурации. SQL-параметры пользовательских значений передаются отдельно.
created_at (timestamptz) преобразуется драйвером pg в Date и сериализуется JSON в ISO UTC.
Неправильный UUID проверяется до SQL. Ошибки операций БД возвращают 503 без деталей подключения.
Токен не хранится в localStorage/sessionStorage и очищается при выходе.
В интерфейсе нет демонстрационных записей или подмены реальных данных.
Интерфейс обновляет список при входе, переключении пространства и кнопкой «Обновить».
Автоматическая подписка на чужие SQL-изменения не реализована.
