## Назначение и устройство

Приложение реализует создание, просмотр, переименование, отметку выполнения
и удаление дел. Интерфейс написан на HTML, CSS и JavaScript без отдельного
фронтенд-фреймворка. Сервер использует Express и TypeScript, данные хранятся
в PostgreSQL. Разделение на конфигурацию, авторизацию, маршруты, подключение
к БД и статический интерфейс упрощает проверку и сопровождение.

Приложение опубликовано на Vercel, база размещена в Supabase. Этот вариант
выбран после практической проверки подключения и независимого доступа
к учебным данным. Supabase Free — постоянный бесплатный тариф с квотами,
а не временный грант. При низкой активности проект может приостанавливаться,
поэтому перед проверкой необходимо убедиться, что база активна.

## Данные и безопасность

Таблица public.tasks хранит задачи одного автора с разделением по runId.
Соответствие физических столбцов и полей API приведено ниже. Сервер задаёт
UUID, логин владельца, время создания и начальное done=false. Время API
возвращается строкой UTC в ISO 8601. Пользовательские значения передаются
в SQL параметрами; выборки ограничены логином из конфигурации.

Все маршруты /api/ требуют заголовок Authorization: Bearer <токен>.
Токен вводится в интерфейсе и не встроен в исходники. GET /login/
доступен без токена и возвращает логин Moodle. После входа интерфейс
показывает сведения автора. В пространстве manual создано персональное
дело «Итоговая работа 24.10.2026: rozhdestvo_v».

Приложение использует роль todo_app. Проверяющему предоставляется отдельная
роль todo_reviewer с CRUD-доступом к учебной таблице без административных
прав. Подключение к Supabase использует TLS с проверкой CA-сертификата.
Токен API и реквизиты БД передаются преподавателю лично в Moodle;
публичный репозиторий содержит только примеры конфигурации.

## Воспроизводимый запуск

Локально использован Node.js 20.15.0, на Vercel настроен Node.js 22.x.
Версия PostgreSQL в Supabase — 17.12. Точные зависимости закреплены
в package-lock.json; основные пакеты — Express 5.3.0, pg 8.23.1,
TypeScript 5.9.3 и @vercel/functions 3.11.3.

Для запуска скопируйте пример окружения, заполните конфигурацию и выполните
команды ниже. Для новой базы сначала примените SQL-схему от владельца БД.
Инициализация не должна выполняться ограниченной ролью приложения.
Существующую рабочую базу повторно инициализировать не требуется.

На Vercel переменные задаются в настройках проекта. CA передаётся через
DB_SSL_CA_BASE64; локально можно использовать DB_SSL_CA_PATH.
Параметры sslmode и sslrootcert в DATABASE_URL не добавляются: TLS
настраивается приложением.

## Выполненные проверки

На опубликованной версии проверены CRUD и сохранение изменений после
перезагрузки страницы. Запись и изменение через приложение подтверждены
прямыми SQL-запросами. Изменение и удаление через независимое подключение
отображаются в интерфейсе после обновления. Проверены публичный /login/,
ответы 401 без правильного токена, 400 при отсутствии runId и неверном UUID,
404 для отсутствующей задачи. Эти проверки не заменяют полный набор тестов
валидации. Приложение и база должны оставаться доступны на время проверки.

## Установка и запуск

```bash
npm ci
cp .env.example .env
```

Заполните локальный .env. Не добавляйте его в Git.

### Локальная PostgreSQL через Docker

Для локальной БД используется Docker Compose и `DB_SSL=false`.
Пароль в `POSTGRES_PASSWORD` должен совпадать с паролем в локальном
`DATABASE_URL`. Локальная роль `postgres` используется только для
учебного запуска на компьютере; облачное приложение работает под
ограниченной ролью `todo_app`.

Запустите БД:

```bash
docker compose up -d db
docker compose ps
```

Перед инициализацией дождитесь состояния `healthy`.
Этот шаг нужен только при использовании локальной Docker-БД.
Для уже настроенной Supabase запускать Docker не требуется.

### Инициализация и запуск приложения

Для новой БД выполните db/001_tasks.sql через SQL-клиент от владельца БД.
Альтернатива — скрипт с подключением владельца:

```bash
npx tsx scripts/init-db.ts
```

После инициализации используйте подключение ограниченной роли приложения
для облачной БД. Для локального учебного запуска оставьте локальное
подключение, описанное выше. Существующую рабочую БД повторно
инициализировать не требуется.

```bash
npm run typecheck
npm run build
npm start
```

Режим разработки:

```bash
npm run dev
```

## Независимая проверка базы данных

Для преподавателя предусмотрена отдельная роль PostgreSQL
`todo_reviewer`, позволяющая подключиться к той же базе данных,
которую использует приложение.

Пароль передаётся преподавателю отдельно и не публикуется в репозитории.
Аккаунт Supabase для такого подключения не требуется.

### Подключение через psql

Выполните из корня репозитория:

```bash
psql "host=aws-1-eu-west-1.pooler.supabase.com port=5432 dbname=postgres user=todo_reviewer.nwjcazycfriqiqqgdabn sslmode=verify-full sslrootcert=certs/supabase-ca.crt connect_timeout=15" -W
```

Введите пароль роли `todo_reviewer` по запросу.

### Проверка роли и базы данных

```sql
SELECT
    session_user,
    current_user,
    current_database();
```

Ожидаемый результат:

- session_user: todo_reviewer
- current_user: todo_reviewer
- current_database: postgres

### Проверка персональной задачи

```sql
SELECT
    id,
    owner_login,
    title,
    done,
    run_id,
    created_at
FROM public.tasks
WHERE owner_login = 'rozhdestvo_v'
  AND run_id = 'manual'
  AND title = 'Итоговая работа 24.10.2026: rozhdestvo_v';
```

На момент итоговой проверки запрос вернул персональную задачу с ID:
`288d2427-d953-4f6e-b28d-91b490396c2a`.

Для выхода из psql:

```text
\q
```
